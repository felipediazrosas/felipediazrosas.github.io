        N.02 — ENGINEERING

        1. 01

          Interface

        2. 02

          Application

          Server-side logic, auth, and business rules built to be read and changed by someone else later.

        3. 03

        4. 04

        5. 05

        6. 06

        N.03 — AI & AUTOMATION

        AI, built into the workflow

        Agents, embeddings, and language models applied to specific, bounded problems — with a human decision point kept in the loop where it matters.

        Agents

        Bounded automation that acts on defined triggers — a new ticket, a webhook, a schedule — and reports what it did.

        Embeddings & retrieval

        Context pulled from real historical data, not hard-coded rules, so responses stay grounded.

        Human-in-the-loop

        Automated suggestions with an approval step wherever a wrong call has real cost.

        Observability

        Every automated action logged and traceable back to the trigger that caused it.

        N.04 — LEARNING TECHNOLOGY

        Moodle and Brightspace, as connected ecosystems

        Not two pieces of software to configure — two learning ecosystems that need to agree with each other, and with everything around them.

        Moodle

        Plugin development, web service integration, and theming for institutions running Moodle at scale.

        Brightspace / D2L

        Valence API integration, LTI tooling, and gradebook and roster synchronisation.

        Identity & records

        SSO/SAML and student information system integration so accounts and grades stay a single source of truth.

        LTI 1.3

        Tool integrations that meet institutional security and interoperability requirements.

        N.05 — CLOUD & INFRASTRUCTURE

        Infrastructure as a working part of the system

        AWS used deliberately — compute, storage, and data services chosen for the problem, sized for the load, and monitored after launch.

        Compute

        Lambda for event-driven work, ECS where a long-running service makes more sense.

        Data

        RDS and S3, with access boundaries defined through IAM rather than assumed.

        Integration

        API Gateway as the front door for services that other systems depend on.

        Observability

        CloudWatch dashboards and alarms configured before something breaks, not after.
